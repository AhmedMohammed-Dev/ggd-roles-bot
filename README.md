# 🦢 بوت دليل أدوار Goose Goose Duck (بالعربي) — Discord.py

بوت ديسكورد تفاعلي يشرح **أدوار لعبة Goose Goose Duck** بالعربي مع صورها، بواجهة أزرار
(الأزرار والشرح تظهر **لك وحدك** — لا يراها أحد غيرك في الروم).

### 🚀 النشر على Render بنقرة واحدة

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/AhmedMohammed-Dev/ggd-roles-bot)

الزر يقرأ `render.yaml` فيضبط كل شيء تلقائياً، ولا يسألك إلا عن **حقل واحد**:
`DISCORD_TOKEN` (توكن بوتك). ملاحظة: المستودع خاص حالياً — الزر يعمل فوراً بعد أن تجعله
عاماً (Settings → Change visibility) أو بعد أن تسمح لـ Render بالوصول إليه مرة واحدة.

## 🚀 التشغيل محلياً (3 دقائق)

### 1) إنشاء التطبيق على Discord

1. افتح <https://discord.com/developers/applications> → **New Application** وسمّها مثلاً `GGD Roles`.
2. من قائمة **Bot** في اليسار → اضغط **Reset Token** ثم **Copy** (هذا هو التوكن — لا تشاركه مع أحد).
3. في نفس الصفحة، انزل إلى **Privileged Gateway Intents**:
   - اتركها **مغلقة** إن كنت ستستخدم `/roles` فقط ✅ (هذا الأكثر أماناً).
   - فعّل **Message Content Intent** فقط إن أردت استخدام أمر `!roles`.
4. من **OAuth2 → General** انسخ **Client ID**، ثم استخدم رابط الدعوة التالي بعد تبديل `YOUR_APP_ID`:

```
https://discord.com/api/oauth2/authorize?client_id=YOUR_APP_ID&permissions=19456&scope=bot%20applications.commands
```

> الصلاحيات المطلوبة هي فقط: عرض الروم + إرسال الرسائل + إدراج روابط (Embed).
> **لا تمنح البوت صلاحية Administrator أبداً** — لا يحتاجها.

### 2) التهيئة والتشغيل

**أسهل طريقة (تعمل كل شيء وحدها):** اضغط مرتين على `START.bat` في ويندوز، أو `bash start.sh` في لينكس/ماك.

أو يدوياً:

```bash
cd ggd-roles-bot
python -m venv .venv
source .venv/bin/activate          # على ويندوز: .venv\Scripts\activate
pip install -r requirements.txt

python setup_discord.py            # يضبط GUILD_ID تلقائياً ويطبع رابط الدعوة
python check_setup.py              # يتأكد أن التوكن موجود ويعمل (اتصال حقيقي بديسكورد)
python bot.py
```

> ملف **`.env`** موجود في المشروع وجاهز — المطلوب منك فقط فتحه ولصق التوكن أمام `DISCORD_TOKEN=`.
> (لا يوجد شيء يُقرأ من ملفات خارجية: `bot.py` يحمل قارئ `.env` المدمج، ولا يستبدل أي متغيّر
> بيئي مضبوط من منصّة الاستضافة — فمتغيّرات Render/Koyeb لها الأولوية دائماً.)

بعد أن تظهر لك رسالة `✅ البوت جاهز`، اكتب في سيرفرك:

```
/roles
```

لتفعيل أمر البريفكس كذلك، ضع في `.env`:

```
ENABLE_PREFIX_COMMANDS=true
GUILD_ID=معرّف_سيرفرك
```

> **لماذا `GUILD_ID`؟** الأمر السلاش العالمي قد يتأخّر ظهوره حتى ساعة، أما أمر السيرفر فيظهر **فوراً**.

### 3) تشغيل الاختبارات (بدون توكن ولا إنترنت)

```bash
python -m unittest -v test_bot.py test_deploy.py
```

> تريد الخطوات مرتّبة في مكان واحد بأبسط شكل؟ افتح **`STEPS.md`**.

## ☁️ الاستضافة المجانية 24/7

> ⚠️ **بصراحة كاملة:** لا أحد — ولا أنا — يستطيع الدخول على حسابك بكلمة مرورك، ولا يصلح أن تعطي كلمة
> مرورك (أو رمز 2FA) لأي شخص. لكن يوجد حلّ وسطي عملي: **مفتاح مؤقت قابل للإلغاء** يسمح بأن ينفّذ
> البرنامج الخطوات نيابة عنك، ثم تلغيه في ثانية.
>
> **الطريق السريع ➜ أمر واحد:** أنشئ المفتاحين (القسم ⚡ في `STEPS.md`)، ضعهما في ملف
> `.deploy_secrets` على جهازك (مذكور في `.gitignore`)، ثم:
>
> ```bash
> python deploy.py --check     # فحص المفتاحين فقط، بلا أي تغيير
> python deploy.py             # ينشئ مستودع GitHub + يرفع الكود + ينشر على Render + يضبط كل شيء
> ```
>
> لا يُطبع أي مفتاح على الشاشة أبداً، ويوجد اختبار يفشل لو تسرّب مفتاح إلى الكود أو إلى Git.
> أما الخطوات اليدوية أدناه فتبقى موجودة كمرجع وبديل إن رغبت.

### الخيار الأول (الموصى به): Render — مجاني

Render يوفّر خدمة ويب مجانية، لكنه **يُنيّمها بعد 15 دقيقة** بلا زيارات.
لذلك الكود مدمج فيه **قرع ذاتي**: البوت يزور نفسه كل 10 دقائق فيبقى مستيقظاً 24/7.

**الطريقة (نشر تلقائي من GitHub):**

1. ارفع مجلد المشروع إلى مستودع **GitHub خاص (Private)** — ملف `.gitignore` يمنع رفع `.env` تلقائياً.
2. افتح <https://dashboard.render.com> → **New → Web Service** → اختر المستودع.
3. Render يقرأ `render.yaml` تلقائياً. تأكد من:
   - **Build Command:** `pip install --no-cache-dir -r requirements.txt`
   - **Start Command:** `python -u bot.py`
   - **Health Check Path:** `/healthz`
4. في **Environment** أضف:

   | المتغير | القيمة |
   |---|---|
   | `DISCORD_TOKEN` | توكن البوت (سرّي) |
   | `GUILD_ID` | معرّف سيرفرك |
   | `PUBLIC_URL` | رابط الخدمة بعد النشر، مثل `https://ggd-roles-bot.onrender.com` |

5. **Create Web Service** وانتظر انتهاء النشر، ثم ضع `PUBLIC_URL` إن لم تكن متأكداً منه وأعد النشر.
6. شغّل `/roles` في سيرفرك ✅

**نقاط مهمة للاستمرار 24/7:**
- استخدم **خدمة ويب واحدة فقط**: الحصة المجانية 750 ساعة شهرياً = خدمة واحدة تعمل طوال الشهر.
- لا تجعل `SELF_PING_SECONDS` أكبر من 900 ثانية (15 دقيقة = وقت النوم).
- Render يشترط أن يكون الموقع **قيد الاستخدام الفعلي** — لا تستخدم القرع لخدمات لا تُستخدم.

**بديل إن لم ترغب في القرع الذاتي:** أضف `https://uptimerobot.com` (مجاني) ليضرب الرابط كل 5 دقائق.

### الخيار الثاني: Koyeb — مجاني (خدمة واحدة)

خطة **Hobby** المجانية في Koyeb تسمح بخدمة ويب واحدة (512 ميجابايت رام، 0.1 vCPU):

1. <https://app.koyeb.com> → **Create Service** → **GitHub** → اختر المستودع.
2. اختر نوع النشر **Dockerfile** (الملف موجود في المشروع جاهزاً، ويشغّل البوت بمستخدم غير جذري).
3. أضف نفس متغيرات البيئة (`DISCORD_TOKEN`, `GUILD_ID`, `PUBLIC_URL`).
4. اجعل المنفذ **8080** وأضف مسار الفحص `/healthz`.

### الخيار الثالث: أي خادم (VPS / Oracle Cloud Always Free)

```bash
git clone https://github.com/USERNAME/ggd-roles-bot.git && cd ggd-roles-bot
cp .env.example .env && nano .env       # ضع التوكن
docker build -t ggd-bot . && docker run -d --restart=always --env-file .env -p 8080:8080 ggd-bot
```

`--restart=always` يجعل البوت يعود تلقائياً بعد أي إعادة تشغيل أو سقوط.

## 🛡️ الأمان — قائمة تحقّق

الكود مكتوب بحيث **لا يمكن** استغلاله لاختراق سيرفرك:

- ✅ **لا يوجد توكن داخل الكود** — يُقرأ من `DISCORD_TOKEN` فقط، والبرنامج يرفض العمل بدونه.
  وهناك اختبار (`test_no_hardcoded_discord_token`) يفشل لو تسرّب توكن إلى الملف.
- ✅ `.gitignore` يمنع رفع `.env` وكل ما يحتوي أسراراً.
- ✅ **أقل صلاحيات ممكنة:** البوت لا يطلب `Administrator` ولا يقرأ محتوى الرسائل افتراضياً
  (`message_content` معطّل إلا إذا فعّلته أنت).
- ✅ **قائمة بيضاء للسيرفرات** (`ALLOWED_GUILD_IDS`): البوت يخرج تلقائياً من أي سيرفر غير مسموح.
- ✅ **حماية من السبام:** فترة منع بين ضغطات الأزرار (`ACTION_COOLDOWN_SECONDS`)
  وفترة تهدئة لأمر `!roles` لكل مستخدم ولكل روم.
- ✅ **خادم Flask آمن:** وضع Debug مُعطّل (Debug هو أشهر سبب لاختراق تطبيقات Flask)،
  نقطة نهاية واحدة للفحص فقط بلا أي أمر تنفيذي، حجم الطلبات محدود، وترويسات حماية مضافة.
- ✅ **مفتاح اختياري لنقطة الفحص** (`HEALTH_TOKEN`) بمقارنة آمنة ضد هجمات التوقيت.
- ✅ **لا استدعاءات خطيرة:** لا `eval` ولا `exec` ولا `os.system` ولا `pickle`،
  والكود لا يكتب أي ملف على القرص.
- ✅ **القيم المُرسلة للـ Embed مأخوذة من قاموسك أنت** — لا يستطيع أي مستخدم حقن نص في الرسائل.
- ✅ الحاوية في Dockerfile تعمل بمستخدم **غير جذري (non-root)**.
- ✅ `allowed_mentions` تمنع أي منشن `@everyone` أو `@here`.

**نصائح إضافية لك:**

1. إن تسرّب التوكن لأي سبب: **Reset Token** فوراً من لوحة المطوّرين (التوكن القديم يتوقف حالاً).
2. أضف البوت لسيرفرات تعرفها فقط، وفعّل التحقق بخطوتين على حساب ديسكورد الخاص بك.
3. على Discord Developer Portal → Bot، أغلق **Public Bot** إن أردت أن يضيفه أنت وحدك.

## 🧩 كيف تضيف دوراً جديداً؟

افتح `bot.py`، اذهب إلى قسم **`ROLES`**، وانسخ هذا القالب:

```python
"my_role": {                                   # ← معرّف إنجليزي صغير (بلا مسافات)
    "name_ar": "اسم الدور بالعربي",
    "name_en": "Role Name",
    "emoji": "🎯",
    "team": "goose",                           # goose أو duck أو neutral
    "goal": "هدف الدور في اللعبة…",
    "how": "طريقة اللعب خطوة بخطوة…",
    "tips": "• نصيحة أولى\n• نصيحة ثانية",     # \n = سطر جديد
    "image": "https://رابط-الصورة.png",       # أو None إن لم توجد صورة
    # اختياريان — اتركهما فارغين للوضع الكلاسيكي وكل الخرائط:
    "maps": "خريطة Godzilla فقط",              # اذكره فقط إن كان الدور مقصوراً على خرائط معيّنة
    "mode": "corruption",                      # corruption / trick_or_treat / tlc / hoot_seek
},
```

هذا كل شيء — الأزرار والصفحات والألوان تُبنى تلقائياً.
لتُظهر الدور في الصفحة الأولى، أضف معرّفه إلى `FEATURED_ROLES`.
وإذا أضفت دوراً جديداً أضف مفتاحه أيضاً إلى قائمة `EXPECTED` في `test_bot.py`
حتى يبقى اختبار اكتمال الدليل صادقاً، ثم شغّل `python check_images.py` للتأكد من صورته.

**لماذا لا يوجد زر أصفر؟** ديسكورد يوفّر 4 أنماط أزرار فقط (أخضر/أحمر/أزرق/رمادي).
لذلك: الإوز أخضر، البط أحمر، والمحايدون رماديون — والتمييز الحقيقي بالأصفر يظهر في
**لون الرسالة نفسها** 🟡.

## 🔧 حل المشكلات

| المشكلة | الحل |
|---|---|
| `❌ لم أجد التوكن` | احفظ `.env` بعد لصق التوكن، أو شغّل `python check_setup.py` لمعرفة السبب |
| `❌ قيمة DISCORD_TOKEN لا تبدو توكن صحيح` | نسخت جزءاً من التوكن أو الصقت النصّ التجريبي — أعد Copy من زر Reset Token |
| الأمر `/roles` لا يظهر | اترك البوت دقيقة، أو ضع `GUILD_ID` ليتسجّل فوراً (قد تحتاج إعادة تشغيل البوت) |
| `!roles` لا يعمل | فعّل `ENABLE_PREFIX_COMMANDS=true` **و** فعّل Message Content Intent من لوحة المطوّرين |
| الأزرار ظهرت لكن لا تستجيب | البوت متوقف أو أُعيد تشغيله — أعد إرسال اللوحة بـ `/roles` |
| البوت لا يعمل على الاستضافة ولا توجد رسالة | افتح رابط الخدمة + `/healthz` في المتصفح — سيعرض `{"status":"error","reason":"…"}` بالسبب مكتوباً (مثل توكن فارغ أو غير صحيح)، ويعرض `"roles": 86` في النسخة السليمة |
| الصور لا تظهر | شغّل `python check_images.py` ليخبرك بالرابط المكسور بالضبط، ثم استبدله برابط `https` مباشر ينتهي بـ `.png`/`.jpg` |
| الزر يرد «انتظر ثانية» | هذا حماية السبام، يمكن تعديله بـ `ACTION_COOLDOWN_SECONDS=0` (غير مُستحسن) |
| السيرفر المجاني ينام | تأكد من ضبط `PUBLIC_URL` بشكل صحيح وأن `SELF_PING_SECONDS` أقل من 900 |
